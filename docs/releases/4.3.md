# LUMEN 4.3

## Independent app packages

A `.lumen-app` installs its own static ARMv7 executable and assets through File Transfer → Apps, without rebuilding/replacing the system executable or restarting LUMEN. The versioned SDK uses bounded, nonblocking process IPC and system-rendered UI. Keyboard input, dropdown selection, notifications, internal Back navigation and Markdown Reader requests use the system's existing implementations.

One origin-neutral catalog, package ID and installation contract cover all entries. Updating an existing ID replaces its launcher entry rather than creating a custom duplicate. Personal state is outside replaceable code. Native packages are trusted code, not security sandboxes.

Frog Solitaire and Sliding Puzzle are now shipped independent packages. Other older views still have linked compatibility implementations; the framework accepts standalone replacements for their IDs, but those implementations have not all been ported into independent artifacts. This release establishes the real package/runtime boundary rather than claiming that migration is complete.

The web prompt uses the standalone SDK and package upload endpoint. The release includes an SDK ZIP that builds the included example using only Zig and the app's sources. App uploads do not trigger a LUMEN restart.

## Complete GitHub updates

System → Update now downloads a full runtime package, including changed fonts, artwork, dictionaries, launchers, program and shipped app archives. Existing asset equality is no longer required. Overall and per-file SHA-256, lengths, package paths and native executable checks precede activation. User data, books, installed app folders and recovery controls cannot be package targets.

A durable helper backs up changed originals, writes a recovery journal, and activates staged files. Interrupted or unkept trials restore the previous runtime. Keep commits before deleting rollback files. Backups do not accumulate across GitHub updates.

One USB installation of this version establishes the complete updater. Future releases use GitHub even when runtime resources change. This updates LUMEN, not Amazon firmware.

The Publish Kindle update workflow builds/publishes a new VERSION after Native checks on main succeed. Existing releases are not overwritten. Assets include USB ZIP/SHA, full `.lumen-system`, metadata, SDK and the independent app packages.

## Checks

Native and ARM builds; existing focused UI/default tests; app process rendering/input; independently replacing an app without changing the system executable; authenticated HTTP app installation/catalog; full resource replacement, rejected private paths, trial rollback, Keep and simulated interruption during activation. Physical Wi-Fi activation still needs a device session outside USB mode.
