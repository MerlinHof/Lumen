APP PROTOCOL 1 — one package identity and contract for all apps:
1. Get the SDK from the installed LUMEN release at
https://github.com/MerlinHof/Lumen. Read tools/sdk/lumen_app.h,
tools/build-app.py and docs/app-packages.md. Use the matching SDK release.
No MuPDF build or system compilation is needed. The SDK is a small C client.
The SDK ZIP release includes a ready-to-use standalone build script and examples.
2. Make a folder containing your C sources and package.json:
{"format":"lumen-app-1","api":1,"id":"your.reverse-domain.app",
 "name":"Your App","version":"1.0.0","sources":["main.c"]}
Use a stable ID. Updating an existing app uses that SAME ID, never a duplicate.
Apps shipped with LUMEN have IDs such as lumen.calculator, lumen.notes and
lumen.sliding-puzzle; the same package mechanism can replace their implementation.
Do not replace an existing app unless the user requested it.
3. Build only this app with:
python3 tools/build-app.py path/to/package.json --target kindle
The standalone SDK uses python3 build-app.py package.json instead.
Use the pinned Zig compiler or set ZIG to its executable. Target ARMv7 static
musl; do not depend on Amazon libraries or access the framebuffer/input devices.
4. Runtime protocol is bounded newline JSON on stdin/stdout. Use lumen_run,
lumen_begin/end and ui_paint_* wrappers from the SDK. Receive open, input,
pause, resume and text events. UI is 600x800; the shared status bar owns y<56.
Use the system's text roles, heading, buttons, icon controls, surfaces, ellipses,
lines and hitboxes. You send UI descriptions; LUMEN renders with its own rounding,
antialiasing, typography, touch feedback and refresh engine. No private refresh
loops, delays or background animations. Keep stdout exclusively for protocol.
5. For keyboard input send lumen_request("input",title,current_text,action).
Read the returned text event. For a rich document use the "reader" request with
Markdown in text and a title; LUMEN opens its shared Reader with user preferences.
"notify" shows the shared notification. Use the protocol's "open" intent for
navigation to another app. Do not implement another keyboard or Reader.
6. Store personal state only under LUMEN_APP_DATA; it survives app/system updates.
Use validated, bounded files and atomic saves. Keep work asynchronous and finite.
Apps run as separate processes, but are TRUSTED native programs, not security
sandboxes. Do not start/stop firmware services. Do not read unrelated user data.
7. Design: calm paper-native tools; white space, dark ink, confident serif headings,
quiet secondary text, comfortable 44px touch targets, consistent 28px margins.
Use the shared UI rather than a generic web/phone aesthetic. Black primary accents
are deliberate; no faint hairlines. Use the system icons at toolbar sizes.
For a launcher icon add icon.pgm as an asset: binary P5, exactly 76x76 grayscale,
header "P5\n76 76\n255\n". Match the engraved pencil/ink objects: deep blacks,
open white paper, uniform detail density, no squircle frame baked into the image.
Provide DE/EN/FR text according to the open event's language (0/1/2).
8. Test the app's input/state and host build briefly. Keep all generated files,
SDK dependencies and local credentials out of Git. Do not modify the OS to add
an app. The result is a .lumen-app ZIP with its manifest, executable and assets.
9. Install with a single authenticated PUT:
PUT DEVICE_URL/api/apps/install
Authorization: Bearer PAIRING_CODE
Content-Type: application/octet-stream
Body: the .lumen-app bytes. Expect HTTP 201. GET /api/apps lists the unified
catalog. The app appears in Home; LUMEN does NOT restart. If the code expires,
ask for the current code. Do not guess it or retry unauthenticated repeatedly.
